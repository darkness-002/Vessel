1. EXECUTIVE SUMMARY & INITIAL STATE
--------------------------------------------------------------------------------
At the start of the session, the repository was thoroughly analyzed:
- Vessel is an ultra-lightweight desktop web-app container engine designed to
  turn web applications (ChatGPT, Linear, Slack, Notion, GitHub) into dedicated
  native windows with isolated filesystem directories (cookies, cache, storage).
- Architectural concept: Decoupled Manager Mode (`vessel`) vs. Container Mode
  (`vessel --run-container <ID>`), meaning the Manager DOM is never loaded or
  rendered when launching a container directly.
- Academic Evaluation: Assessed as an undergraduate/master's Final Year Project (FYP).
  Initially rated at 5.5 / 10 (C+/B-) due to reliance on default Tauri/WebView2
  features without custom low-level systems algorithms, background resource
  supervision, encryption, or research benchmarking.
- Mission: Elevate Vessel to a top-tier systems engineering project (8.5 - 9.0 / 10)
  by implementing three major pillars:
    1. Intelligent Process Supervision & Idle Resource Hibernation Engine
    2. Hardware-Backed Encrypted Profile Vaults (AES-256-GCM + Argon2id + Keyring)
    3. Modern Svelte 5 Dashboard with Live Telemetry and Vault Controls
    4. Automated Empirical Benchmarking Harness & Academic Publication Suite

PILLAR 1: INTELLIGENT PROCESS SUPERVISOR & HIBERNATION ENGINE
--------------------------------------------------------------------------------
File Created: `src-tauri/src/supervisor.rs`
Files Modified: `src-tauri/src/main.rs`, `src-tauri/src/commands.rs`, `src-tauri/Cargo.toml`

Key Capabilities:
- State Machine: Tracks container runtime states (`Running`, `Idle`, `Hibernated`, `Closed`).
- Telemetry Engine: Uses the `sysinfo` crate (v0.39) to measure real-time Resident
  Set Size (RSS Memory in MB) and CPU % across process trees (parent and child
  WebView2 / WebKit subprocesses).
- Background Idle Detection: Uses a Tokio background task (`tauri::async_runtime::spawn`)
  that monitors window focus and idle time. If an unfocused container exceeds the
  idle threshold (default 15 minutes, configurable), it executes a graceful hibernation routine:
    * Persists the active navigation URL route.
    * Destroys the underlying OS `WebviewWindow` process via `win.destroy()`.
    * Reclaims working set memory back to the host operating system (dropping to 0 MB).
    * Retains a lightweight in-memory metadata stub.
- Seamless Wake: On user click/focus, recreates the window directly pointing to
  the persisted navigation route.
- Native Win32 Process Extraction: Resolves window thread process IDs on Windows
  via `user32::GetWindowThreadProcessId` from native HWND handles.
- New Tauri IPC Commands:
    * `get_container_metrics()` -> Returns live PID, RSS (MB), CPU (%), status, idle time.
    * `wake_container(id)` -> Dynamically restores a hibernated container window.
    * `force_hibernate_container(id)` -> Immediately forces memory release.

PILLAR 2: HARDWARE-BACKED ENCRYPTED PROFILE VAULTS
--------------------------------------------------------------------------------
File Created: `src-tauri/src/vault.rs`
Files Modified: `src-tauri/src/main.rs`, `src-tauri/src/commands.rs`, `src-tauri/Cargo.toml`

Key Capabilities:
- Symmetric Encryption: Authenticated `AES-256-GCM` (`aes-gcm` v0.11) with 12-byte
  cryptographically random nonces and 16-byte Poly1305 authentication tags.
- Key Derivation Function (KDF): `Argon2id` (`argon2` v0.6) with 16-byte random salts
  for master passphrase key derivation.
- OS Hardware Keyring Integration: Uses the `keyring` crate (v4.2) to store and
  retrieve random 256-bit vault keys from the native OS Credential Manager
  (Windows DPAPI / Credential Vault, macOS Apple Keychain, Linux Secret Service)
  under the service name `vessel_vault`.
- In-Memory Archiving: Streams the entire profile directory (cookies, session SQLite
  databases, LocalStorage, IndexedDB) into an in-memory tar-gzip archive (`tar` + `flate2`)
  before encryption.
- Vault Binary Format:
    [Magic: 10B ("VSSLVAULT1")] [Salt: 16B] [Nonce: 12B] [Ciphertext + Tag]
- Cryptographic Sanitization: Uses the `zeroize` crate to erase plaintext keys and
  archives in memory; securely zeroes on-disk file bytes before deleting unencrypted folders.
- Lifecycle Integration:
    * Pre-Launch: Automatic decryption and unpacking before webview initialization.
    * Post-Close: Asynchronous automatic vault sealing when windows are closed.
    * Permanent Deletion: Purges vault files and deletes OS Keyring credentials on uninstall.
- New Tauri IPC Commands:
    * `lock_container_vault(id)` -> Destroys window and seals data into `<ID>.vault`.
    * `unlock_container_vault(id, passphrase?)` -> Decrypts and unpacks profile archive.
    * `is_vault_locked(id)` -> Returns boolean indicating if container is encrypted at rest.
