TECHNICAL DOCUMENTATION

Built to be understood.

Vessel is an open-source, resource-efficient container engine that runs individual web applications inside physically isolated native webview sandboxes with zero Electron runtime bloat.

Evidence, not estimates. Reproducible host benchmarks and verified isolation primitives.

Architecture & System Design

Vessel separates the supervisory desktop control plane from container runtime web contexts. The supervisor process is written in Rust using Tauri v2, exposing a strictly governed IPC interface to the management frontend while managing each application container in an autonomous OS window.

Native OS WebViews vs Bundled Chromium

Standard desktop web wrappers bundle entire distributions of Chromium and Node.js for every window, consuming 400MB to 1GB of memory per application. Vessel leverages the operating system's built-in web engine:

  • Windows: Microsoft Edge WebView2 (Evergreen Runtime), sharing system memory pages and DirectX hardware acceleration pipelines across all containers.
  • macOS: WebKit (WKWebView), fully integrated into Darwin power management and App Nap scheduling.
  • Linux: WebKitGTK with native Wayland and X11 compositing support.

This architectural shift ensures zero bundled binaries in app release packages, instant cold starts, and minimal battery impact on portable hardware.

Physical Storage Isolation

Unlike typical browser profiles that share indexed databases or unified disk caches, Vessel instructs the underlying webview builder to bind to a distinct data_directory path per container:

src-tauri/src/main.rs :: Container Window Setup 
let profile_dir = profile::get_profile_dir(&id);
let builder = WebviewWindowBuilder::new(app, &win_label, WebviewUrl::External(url))
    .title(&container.name)
    .user_agent(get_stealth_user_agent())
    .data_directory(profile_dir);

When an external link is clicked within a container, Vessel's on_navigation filter compares the destination hostname against the container's registered root domain. External links are intercepted and opened in your default operating system browser via @tauri-apps/plugin-opener, keeping container profile directories sterile.

VSSLVAULT2 Cryptographic Security

Vessel features an encrypted vault engine (VSSLVAULT2) implemented in pure Rust. When a container window is destroyed or sealed, its entire profile directory (cookies, sessions, local storage) is packed into a tar archive and encrypted using authenticated AES-256-GCM.

Vault Component Specification Properties
Magic Header VSSLVAULT2 (10 bytes) Strict file format identification; rejects tampered or legacy v1 headers
Cipher / Mode AES-256-GCM (AEAD) Confidentiality + cryptographic integrity tag; detects tampering instantly
Nonce Generation 96-bit CSPRNG (OsRng) Guarantees fresh nonce per seal; verified by test suites
Key Storage Mode OS Credential Store / Keyring Hardware-backed TPM/Keychain storage with zero cleartext on disk
Passphrase Mode Argon2id KDF (64MB memory, 3 iterations) Memory-hard resistance against GPU brute-force attacks

Benchmark Methodology

All benchmarks are executed via benchmarks/run_benchmarks.py with automated warm-up periods, process tree attribution, and 5 independent trials per workload (N=5):

  • Measurement Tooling: Python 3.11 with psutil polling at 100ms intervals, capturing all child rendering, GPU, and utility processes spawned under the container parent PID.
  • Workloads: Identical authenticated sessions for Spotify, Linear, Slack, GitHub, and Notion launched sequentially and in parallel.
  • Memory Metrics: Physical Working Set RSS (Resident Set Size) in megabytes, verified against Windows Performance Counters.
  • CPU Attribution: Cumulative kernel + user time divided by elapsed wall-clock time across the full process tree.
